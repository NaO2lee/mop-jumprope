## 6. 더블탭 카운팅 버그 (KST 00:38)

**문제**: 심판이 카운트 버튼을 1번 탭했는데 가끔 2씩 증가. 기종 무관 (iOS·Android 모두 발생).

**쟁점**:
- 모바일 브라우저에서 한 번의 손가락 탭이 두 개의 별개 이벤트로 처리될 수 있음:
  - `touchstart` 발화 → 즉시 카운트
  - 300ms 후 합성된 `click` 이벤트 발화 → 또 카운트
- 기존 코드(`judge.html:172`)가 `onclick="addCount(1)"` + `ontouchstart="handleTap(event)"` 둘 다 바인딩하고 있어 mobile 에서 둘 다 fire
- 캐패시티브 노이즈 (손가락이 살짝 미끄러지면 같은 탭이 두 번 감지되는 케이스)

**어떻게 파악**:
- `judge.html:172` 의 이중 이벤트 바인딩 발견
- 기존 `handleTap` 의 150ms throttle 은 있었지만 onclick path 는 throttle 미적용
- iOS Safari 는 `touchstart` 에서 `preventDefault()` 했어도 일부 케이스에 click 합성 → 더블카운트 잔존

**돌파구**:
1. `onclick` 제거 → `onpointerdown` 만 사용 (modern Pointer Events — touch + mouse 통합 이벤트)
2. `handleTap` 에 `preventDefault + stopPropagation` 추가
3. `pointerType==='touch' && isPrimary===false` 체크로 멀티터치 노이즈 차단
4. 디바운스 30ms 로 단축 (150ms 는 빠른 연타도 차단하는 문제)

**진행 결과**:
- ✅ `judge.html:172` 의 +1 버튼 → `onpointerdown` 단일 이벤트
- ✅ `handleTap()` 가드 강화 (preventDefault + stopPropagation + isPrimary + 30ms debounce)
- ✅ touch/mouse 모두 동일 경로로 처리됨 → 기종 의존성 제거
- task #110 완료

## 7. 집계 제출 완료 + 원자성·idempotency (KST 00:55)

**문제**:
- 심판이 "기록 제출" 버튼을 눌렀을 때, 점수가 한쪽 path 에만 들어가고 다른 쪽은 누락되는 케이스 있음 → 운영자 화면에는 "제출됨" 인데 심판 화면에는 "준비됨" 상태 같은 mismatch
- 더블탭으로 같은 제출이 두 번 들어가는 경우 → 두 번째 write 가 첫 번째 덮어쓰면서 score 값이 흔들림
- Firebase write 실패해도 overlay 가 즉시 보여 사용자가 "제출됐다" 착각

**쟁점**:
- Firebase RTDB 는 단일 `.update(updates)` 에서 multi-path 업데이트를 server-side atomic 으로 지원 → 두 path 묶을 수 있음
- idempotency 는 client 측 `_submitting` flag 와 server 측 `submissionId` 양쪽 보호 필요
- 사용자 명시 요청: "집계 제출 완료" 라는 명확한 버튼 이름 + 명시 confirmation

**어떻게 파악**:
- `judge.html:353-367` `submitScore()` — 두 개의 `await db.ref().update()` 분리 호출
- `_submitting` flag 없음, confirm() 없음
- overlay show 가 try 블록 안에 있지만 catch 도 있어 try 가 부분 실패 시 모순된 UI

**돌파구**:
1. **Multi-path atomic update**: `db.ref().update(updates)` 한 번으로 `heats/.../courts/key/*` + `monitoring/judges/courtId/*` 9개 키 동시 갱신
2. **Re-entry guard**: `_submitting` 모듈 로컬 플래그 + 버튼 `disabled` + opacity .5
3. **submissionId**: `${courtId}-${ts}-${random6}` 형태 → 같은 제출 식별, 추후 audit log 에서 dedup 가능
4. **confirm()**: "기록 N개로 제출하시겠습니까?" 명시 확인
5. **UI 갱신은 await 성공 후에만**: 실패 시 overlay 안 뜨고, 토스트로 에러 메시지 표시 (네트워크 확인 안내)
6. **버튼 라벨**: "✓ 기록 제출" → "✓ 집계 제출 완료" (사용자 요청 그대로)

**진행 결과**:
- ✅ `judge.html:352-401` `submitScore()` 재작성
- ✅ atomic single update 로 partial-write 가능성 0
- ✅ 더블탭 시 두 번째 호출 → 즉시 "제출 중..." 토스트 + 차단
- ✅ submissionId 발급 (`{courtId}-{ts}-{rand}`) → Firebase 에 양 path 동일 ID 저장
- ✅ 실패 시 overlay 안 뜨고 토스트로만 알림 → "제출됐다" 착각 제거
- ✅ 버튼 라벨 "✓ 집계 제출 완료" 로 변경
- task #108, #101 완료
